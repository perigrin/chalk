## Executive Summary

The commit ships a working method-parameter ABI — the five places that must agree
on a method's LLVM type do agree, verified end to end for straight-line, inherited,
overridden, `%Str`-aggregate, and mixed-arity shapes. But it introduces a **live
regression**: `_method_param_reprs` derives a method's arity by scanning the body
graph for `Parameter` nodes, and the producer emits no such node for a parameter
the body never reads. `method m($unused) { 42 }` lowered and printed 42 at the
parent; at HEAD it refuses. Roughly 57 of 503 parameterized methods in `lib/Chalk`
have that shape.

A second critical, found by one specialist and confirmed by measurement, is in the
typing half: widening `_seed_direct_call_arg_reprs` to method dispatch made the
`shift @_` recovery arms reachable for methods, where `shift` yields the *invocant*.
The pass now stamps the caller's argument type onto a read that holds the object.

The verifier overturned two specialist claims — see "Corrections" — including
inverting the causal story on a silent miscompile. That correction changes the fix
order and is the most consequential finding in the review.

## Critical Issues

### [C1] A method with an unused parameter refuses to lower (regression)
- **File:** `lib/Chalk/Target/LLVM.pm:459` (`_method_param_reprs`), refusal at `lib/Chalk/Target/LLVM/Context.pm:9168`
- **Bug:** The signature is derived from the body graph's `Parameter` nodes. The
  producer emits **no `Parameter` node for a parameter the body never reads**, so
  `param_reprs` undercounts and the new arity check refuses. The commit's own
  comment — "A method's parameters are exactly its Parameter nodes" — is false: the
  graph records *used* parameters, not *declared* ones.
- **Impact:** Correct Perl that compiled before now refuses. Measured:
  ```
  PARENT 215ffee7: define internal i64 @C__m(i8* %self)   lli: 42   perl: 42
  HEAD   cb16da6d: GAP: Call(method) 'm' passes 1 argument(s) but 'C'::m declares 0
  ```
  Scope: **57 of 503** parameterized methods in `lib/Chalk` have a parameter never
  mentioned in the body (textual scan; an order-of-magnitude figure, not exact).
  These are interface-conformance parameters — e.g. `Bootstrap/Context.pm:37 extend`
  (`%opts`), `Optimizer/Pass.pm:24 run` (`$input`),
  `Semiring/TypeInferenceActions.pm:272 Subscript` (`$ctx`). This is the
  self-hosting path.
- **Suggested fix:** NOT available via the metaobject today. `MOP::Method`'s
  `$params` field (`lib/Chalk/MOP/Method.pm:15`) exists but is never populated —
  the sole loader call site, `lib/Chalk/IR/Analysis.pm:1647`, passes only `graph`
  and `return_type`, and **the wire carries no signature/arity map at all**. So
  either the producer starts emitting declared arity, or the walker is corrected
  (see C3/I2) *and* the sparse/dense index space is fixed (I1) in the same change.
- **Confidence:** High — reproduced independently by three specialists, by the
  verifier, and by the coordinator.
- **Found by:** Logic & Correctness, Error Handling, State & Caching, Contract & Integration

### [C2] Widening the seed pass makes `shift @_` in a method steal the argument's type
- **File:** `lib/Chalk/IR/Analysis.pm:1049-1058`, falling through to `:1090-1120`
- **Bug:** Gating `_seed_direct_call_arg_reprs` on `direct` *or* `method` made the
  `shift @_` / `$_[0]` recovery arms — written for direct subs — reachable for
  method calls. In a method, `shift` yields **the invocant**, not argument 0. But
  `shift @args` has already dropped the invocant, so the arm seeds the *argument's*
  repr onto a read that holds *the object*.
- **Impact:** A stamp that was never derived from anything — the "fill a hole, never
  preempt a source" class this project has shipped a miscompile for before. Measured
  on `method viaargs { my $k = shift; $k }` called with `7`:
  ```
  wire:   Call#2 op=Call name=shift dispatch_kind=builtin  stamp=Scalar   <- honest
  HEAD:   Call#2 op=Call                                   repr=Int      <- fabricated
  PARENT: Call#2 op=Call                                   repr=Scalar
  ```
  Change the caller's argument to `"hello"` and the same read is stamped `Str`.
  Currently masked by C1's arity check refusing the shape first; the mask disappears
  the moment `ArgsSource`-in-methods gets a lowering.
- **Suggested fix:** Skip the recovery arms for method dispatch — their premise
  (`shift @_` binds argument 0) is false there. One line after the `%params` arm:
  `next if $kind eq 'method';`
- **Confidence:** High — coordinator reproduced the stamp change directly.
- **Found by:** Contract & Integration

### [C3] One-armed `if` in a method body is silently miscompiled — PRE-EXISTING, currently masked
- **File:** method-body lowering; surfaced via `lib/Chalk/Target/LLVM.pm:483` (`_graph_all_nodes`)
- **Bug:** `method bump2($k) { if ($n > 5) { $n = $n + $k } return $n }` emits a
  function containing a field load and a return and **nothing else** — no `icmp`, no
  branch, no store, no add. The entire one-armed `if` body is dropped.
- **Impact:** `perl: 13, lli: 10` — a silent wrong answer, the worst outcome under
  this project's GAP-not-miscompile invariant.
- **THIS IS NOT INTRODUCED BY THIS COMMIT.** It reproduces at parent 215ffee7 with
  no walker change involved. cb16da6d's arity check *incidentally hides it* behind a
  refusal. **Consequence for planning: fixing C1 without first fixing this un-masks a
  live silent miscompile.**
- **Suggested fix:** Fix the one-armed-if body lowering first, as its own change.
  Then fix C1.
- **Confidence:** High — verifier reproduced at the parent and read the emitted IR.
- **Found by:** Logic & Correctness (with an inverted causal story), corrected by Verifier

## Important Issues

### [I1] Sparse `Parameter` indices collapse into a dense list — latent, activated by C1's fix
- **File:** `lib/Chalk/Target/LLVM.pm:475` vs `lib/Chalk/Target/LLVM/Context.pm:6573`
- **Bug:** `_method_param_reprs` returns `[ map { $by_index{$_} } sort keys %by_index ]`
  — dense, positional. `_method_param_decl` names by position (`%arg0, %arg1`), but
  `_lower_parameter` returns `"%arg$idx"` from the node's **raw** index. Measured for
  `method m($a,$b,$c) { $a + $c }`: indices `{0,2}`, list length 2, decl
  `i8* %self, i64 %arg0, i64 %arg1`, body would emit `%arg2` — undeclared, and lli
  rejects the module.
- **Impact:** Masked today by C1's arity check firing first. Any fix for C1 that does
  not unify the index space makes this live.
- **Suggested fix:** Return an array indexed by declared index (padding gaps, e.g.
  with `Scalar`), so position and index are the same number by construction.
- **Confidence:** High — verifier measured the mismatch directly.
- **Found by:** Logic & Correctness, Contract & Integration

### [I2] `_graph_all_nodes` reimplements an existing walker, on a false premise
- **File:** `lib/Chalk/Target/LLVM.pm:483` vs `lib/Chalk/IR/Analysis.pm:737`
- **Bug:** The new walker follows only `inputs` and `control_in`. Its comment claims
  "`$g->nodes` walks value inputs only" — `Graph.pm:142` documents the opposite:
  "Walks both `inputs()` and `consumers()` … so a node connected to the graph only
  via a consumer pointer … is still found." The new walker is strictly weaker than
  either `Graph::nodes()` or `Analysis::_all_graph_nodes`, and misses the Parameter
  in a one-armed `if` (measured: 3 nodes / no Parameter vs 6 nodes / index 0).
- **Impact:** Contributes to C1; CLAUDE.md forbids reimplementing existing features,
  and a false comment is what keeps a duplicate alive. Note `Analysis.pm:1073` reads
  the same callee for the same question a third way (`$callee->nodes->@*`).
- **Suggested fix:** Delete `_graph_all_nodes`, call
  `Chalk::IR::Analysis::_all_graph_nodes($g)`. **Do not land alone** — see C3.
- **Confidence:** High.
- **Found by:** Logic & Correctness, Contract & Integration

## Corrections the verifier made to specialist reports

1. **I3 is not a new regression.** The parent refuses the `PadAccess` forwarding shape too, with a different message. Reported as newly-broken; it is an unfixed gap.
2. **C3's miscompile is not caused by the suggested walker fix.** One specialist swapped in `Analysis::_all_graph_nodes`, saw `perl 13 / lli 10`, and concluded the fix converts a refusal into a miscompile. ## Verified clearances (evidence-backed negatives)

- **Parameter-id cache collisions: SAFE.** Ids do collide (`Two::a` and `Two::b` both hold `id=Parameter#2` with different reprs), but each method body gets a fresh `ElaboratedContext->new` inside the per-method loop (`LLVM.pm:888`), so `{cache}` is per-instance. Measured: each define reads its own `%arg0` at its own type; lli matches perl.
- **Fixpoint termination: SAFE.** Instrumented `_seed_direct_call_arg_reprs` — 1 call for the recursive-method case, 2 for two-method and two-callsite cases. No oscillation. The stamp step is a `meet` folding the existing stamp, monotone over a finite lattice.
- **Determinism: SAFE.** Three separate processes produced byte-identical LLVM (`md5 f963ded3…` ×3). `%pending` is keyed by refaddr but sorted by node id before stamping.
- **`_emit_coercion` genuinely refuses.** Driven over all ordered pairs of 16 repr names: 161 refused, 49 converted, **0 silent passthrough**. The commit's claim is verified — no wrong machine type reaches the bitcast fn pointer.
- **`:reader` and stub defines are consistent.** Reader records omit `param_reprs`, so define and vtable cast both resolve to zero arguments.
- **Inherited forwarder carries `param_reprs`.** `_flatten_inheritance` copies `%$pmeth` wholesale; measured `define internal double @Ch__plus(i8* %self, i64 %arg0)` forwarding correctly, output matches perl.
- **Tests are genuinely RED at the parent.** All 4 subtests fail there, and subtest 2 fails for a *different* reason than 1/3/4 — it pins the `Analysis.pm` seeding half. No vacuous-pass path exists in `compile_and_run`.
- **IR suite baseline confirmed.** `Files=140, Tests=997`; the same 4 files fail at HEAD and at the parent. All pre-existing.
